# Мокап-плагин для Figma — механика для Claude

Протокол заданий **v1**. Этот файл — единственное подробное описание механики:
скилл загружает его при каждом запуске. Меняется механика — меняется этот
файл, скилл не трогаем.

## Как это работает

Мокапы рисует плагин мокапов в Figma пользователя (его название — в
`manifest.plugin` или в скилле). Claude его не запускает и сам ничего не
рендерит: он читает файл через Figma MCP (`use_figma`), пишет в файл
**задание**, а открытый плагин опрашивает файл раз в
1,5 с, подхватывает задание и выполняет его тем же рендером, что кнопка Insert.

Перед каждым вызовом `use_figma` загрузи скилл `figma-use`.

Всё общение — shared plugin data, namespace `mockupautopilot`. Значения — JSON-строки.
Обычный `setPluginData` в `use_figma` не работает, только `setSharedPluginData`.

| Узел | Ключ | Пишет | Что |
|---|---|---|---|
| `figma.root` | `manifest` | плагин | что плагин умеет сейчас |
| `figma.root` | `request` | Claude | задание |
| `figma.root` | `status` | плагин | ход и итог задания |
| фрейм мокапа | `params` | плагин | из чего собран мокап |

## manifest — что умеет плагин

Ракурсы, устройства и цвета **никогда не бери из головы или из этого файла** —
только из манифеста. Их список растёт: появляются новые ракурсы и цветовые
схемы, и манифест узнаёт о них сам.

```json
{"v":1, "plugin":"<название плагина>", "mockupHeight":1080,
 "templates":[
   {"id":"iphone-right", "device":"iphone", "angle":"right", "name":"Right 3/4",
    "frame":[402,874], "colors":["<цвет 1>","<цвет 2>"], "hint":"…"}
 ]}
```

- `v` — версия протокола плагина. Если больше той, что в заголовке этого файла,
  плагин новее описания: работай по этому файлу, но предупреди пользователя.
- `templates` — в порядке панели плагина. Первый шаблон устройства — его
  ракурс по умолчанию.
- `device`, `angle` — как их называть в задании. `name` — подпись в панели.
- `hint` — необязательно: как ракурс называют люди. Сопоставляй слова из запроса
  («в анфас», «сверху», «три четверти влево») с `angle`, `name` и `hint`.
  Не уверен, какой шаблон имеется в виду, — спроси, перечислив варианты
  по `name`.
- `frame` — размер макета в pt, под который нарисован экран. По нему видно
  устройство кадра: ≈402×874 — iPhone, ≈360×780 — Android.
- `colors` — цвета **этого** шаблона. Первый — рабочий, он же по умолчанию.
  У разных шаблонов наборы могут отличаться: проверяй цвет по каждому.
- `mockupHeight` — высота готового мокапа в pt. Ширина зависит от ракурса
  (сейчас 0,53–0,6 высоты), поэтому ряды проще отдавать сетке `layout`: она
  шагает по фактической ширине каждого мокапа.

Пустой манифест — плагин в этом файле ещё не открывали.

## request — задание

```json
{"v":1, "id":"req-1790000000000",
 "layout":{"x":0, "y":1100, "cols":4, "gap":100},
 "items":[
   {"source":"10:62", "template":"iphone-right", "color":"<цвет>", "name":"Home — Right"},
   {"source":"10:26", "device":"android", "angle":"front"},
   {"replace":"12:5", "color":"<другой цвет>"},
   {"source":"10:94", "template":"iphone-front", "x":3000, "y":0, "parent":"10:1"}
 ]}
```

- `id` — новый и уникальный для каждого задания, например `"req-" + Date.now()`.
  Задание с уже выполненным `id` повторно не выполняется.
- Пункт = один мокап. Порядок пунктов = порядок в сетке.
- `source` — id кадра с дизайном. Экспорт 4×.
- `template` — id из манифеста; либо `device` + `angle`. Не сказано ничего —
  первый шаблон из манифеста.
- `color` — имя из `colors` шаблона; регистр и пробелы не важны. Не сказано —
  рабочий. Цвет, которого у шаблона нет, — ошибка пункта.
- `name` — имя фрейма мокапа. По умолчанию «<имя кадра> — <name шаблона>».
- `replace` — перерисовать существующий мокап на его месте: тот же родитель,
  порядок слоёв и координаты. Чего не сказано — берётся из его `params`
  (источник, шаблон, цвет). Новый экран в старом мокапе — `replace` + `source`.
- `x`, `y` — координаты мокапа в системе родителя; `parent` — id секции или
  фрейма. Без `x`/`y` — сетка `layout`, без `parent` — страница исходного кадра.
- `layout`: `x`, `y` — левый верхний угол сетки. Без них сетка встаёт на 400 pt
  правее всех исходных кадров, по верхнему краю. `cols` — в ряд (4),
  `gap` — зазор (100).

Хайлайты (вылетающие карточки) заданием не делаются — только руками в плагине.

## status — ход и итог

```json
{"id":"req-…", "state":"running", "at":1790000000000,
 "done":3, "total":5, "ok":3,
 "results":[{"i":0, "id":"20:1"}, {"i":1, "error":"Frame 10:26 not found"},
            {"i":2, "id":"20:9", "replaced":"12:5"}]}
```

`state`: `running` → `done` (или `failed` при ошибке всего задания, тогда есть
`error`). В `done` есть `failed` — число неудачных пунктов. `results[].i` —
индекс пункта, `id` — созданный мокап.

## params — на каждом мокапе

```json
{"v":1, "source":"10:62", "template":"iphone-right", "color":"<цвет>", "highlights":0}
```

Мокап плагина узнаётся по непустому `params`, в том числе вставленный руками.
`source: null` — дизайн загружали с диска, перерисовать можно только с новым
`source`. `highlights > 0` — при перерисовке карточки пропадут: предупреди.

## Порядок работы

1. **Ссылка.** `fileKey` и `node-id` из URL (`10790-24017` → `10790:24017`).
   Нет ссылки — попроси.
2. **Один read-only вызов:** `manifest`, `status`, и кадры нужной страницы или
   секции — id, имя, тип, размер, позиция, родитель, `params`.
3. **Разбор.** Инструкцию — в таблицу «кадр → шаблон, цвет, место». Двусмысленно
   (какие кадры входят, какой ракурс, порядок) — покажи таблицу коротко и
   спроси. Однозначно — сразу дальше.
4. **Задание.** Записать `request`. Размести ряд так, чтобы он не налезал на кадры:
   например `y` = низ самого нижнего кадра + 200.
5. **Ожидание.** Читать `status` раз в ~5 с. Нет статуса с этим `id` за 15 с —
   плагин закрыт: попроси открыть плагин в этом файле (меню Plugins или кнопка
   плагина в правой панели, когда ничего не выделено).
   Задание ждёт в файле, переписывать не надо.
6. **Итог.** `done` → сверить `results`, коротко доложить; ошибки — объяснить и
   предложить правку.

Двигать, выстраивать, переименовывать, группировать, удалять мокапы — сам через
`use_figma`, без задания. Перерисовка (ракурс, цвет, экран) — только заданием.

## Шаблоны вызовов

Чтение (страница `PAGE_ID`):

```js
const page = await figma.getNodeByIdAsync("PAGE_ID");
await figma.setCurrentPageAsync(page);
const g = k => figma.root.getSharedPluginData("mockupautopilot", k);
const frames = page.children.map(n => ({ id: n.id, name: n.name, type: n.type,
  x: Math.round(n.x), y: Math.round(n.y), w: Math.round(n.width), h: Math.round(n.height),
  params: n.getSharedPluginData("mockupautopilot", "params") || null }));
return { manifest: g("manifest"), status: g("status"), frames };
```

Для секции — то же по `section.children`.

Запись задания:

```js
const request = { v: 1, id: "req-" + Date.now(), layout: { x: 0, y: 1100 }, items: [ /* … */ ] };
figma.root.setSharedPluginData("mockupautopilot", "request", JSON.stringify(request));
return { id: request.id };
```

Статус:

```js
return figma.root.getSharedPluginData("mockupautopilot", "status");
```
